# 登录、自动续期与退出：逐块阅读

完整流程：账号密码 → 验证 → 建立会话 → 返回两种凭据 → 前端按到期时间续期 → 保持当前页面。

## 1. 配置和生命周期

`core/config.py` 读取本机 `.env`。`JWT_SECRET_KEY` 是至少 32 字符的独立随机密钥；`JWT_ACCESS_TOKEN_EXPIRE_MINUTES` 默认 30，`AUTH_REFRESH_WINDOW_HOURS` 默认 12。真实密钥不提交 Git。

`main.py` 创建数据库会话工厂、密码工具、JWT 工具、备用密码哈希以及续期凭据工具。重启不会重新生成本机密钥。首次克隆项目需要自行生成并填写密钥：

```powershell
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
```

当前电脑已配置密钥，无需重新生成。

## 2. 数据和接口约定

- `domain/login_session.py`：`LoginSession` 保存用户、创建时间、最后续期时间、窗口到期时间和撤销状态；`RefreshGrant` 表示一份续期凭据及轮换状态。
- `application/ports/token_service.py`：约定签发访问令牌、验证并返回 `AccessIdentity(user_id, session_id)`。
- `application/ports/auth_sessions.py`：约定会话存储及高熵续期凭据的生成、摘要和后继恢复。
- `UserUnitOfWork` 同时提供用户仓储、会话仓储和提交，保证业务写入属于同一事务。

## 3. 两种凭据各做什么

| 凭据 | 作用 | 默认有效期 |
| --- | --- | --- |
| 访问 JWT | 调用 `/me` 以及未来受保护接口 | 30 分钟 |
| 续期凭据 | 在访问令牌到期前后申请新凭据 | 最后成功轮换后 12 小时 |

JWT 包含用户 ID `sub`、会话 ID `sid`、签发和到期时间、用途、签发方、接收方及唯一编号 `jti`。固定使用 HS256 签名，严格验证算法、签名、有效期和必要字段。载荷不放密码或密码哈希。签名不是对载荷加密。

`infrastructure/security/token_service.py` 负责 JWT；`refresh_credentials.py` 负责高熵续期凭据。续期凭据由会话编号和秘密部分组成，数据库仅保存完整凭据的 SHA-256 摘要，不存原文。

## 4. MySQL 会话存储

迁移 `0002` 新增两张表，保留原有 `users` 数据：

- `auth_sessions`：一次登录对应一个会话，记录所属用户、最后续期、到期、撤销时间。
- `auth_refresh_tokens`：记录凭据摘要、是否已使用、请求编号、后继摘要，用于轮换和识别重放。

会话仓储在 `infrastructure/repositories/auth_sessions.py`。写操作先锁定会话，再读取凭据最新状态，避免并发重复轮换；提交仍由业务控制。删除测试用户时，外键会级联清理其测试会话。

## 5. 登录业务

`AuthenticationService.login()`：规范化账号 → 查询用户 → 验证密码和启用状态 → 创建会话和初始续期摘要 → 签发带 `sid` 的 JWT → 提交 → 返回公开用户和两种凭据。

账号不存在也用备用哈希做一次验证；账号不存在、密码错误或停用，统一提示“账号或密码错误”。登录不重新套用注册时的最小长度、弱密码规则。

`current_user()`：先验证 JWT，再检查数据库会话未撤销、未到期、属于令牌中的用户，最后查用户最新状态。退出或停用后不能继续使用已有 JWT。

## 6. 续期、重试和退出

`POST /api/auth/refresh` 接收 `refresh_token` 和 UUID `request_id`：

1. 查询摘要并锁住会话，检查到期和账号状态。
2. 未使用的凭据：将其标为已使用，保存本次编号与后继摘要，新建后继凭据记录，延长 12 小时窗口，提交后返回结果。
3. 相同旧凭据、相同请求编号，且后继还没继续轮换：恢复同一次操作的结果，不重复轮换、不重复延长窗口。
4. 旧凭据被用于不同操作或其后继已继续使用：撤销该会话，要求重新登录。

后继秘密由独立的 HMAC 子密钥和操作输入确定性计算，响应丢失后能重建，无需保存明文。原凭据不能启动新的续期操作。

`logout()` 接受本会话已签发的续期凭据并撤销会话，因此续期前后的 JWT 都会失效。退出重复调用可安全返回成功。客户端在网络不可用时先退出当前标签页，并明确提示服务器退出暂未确认。

## 7. HTTP 边界

- `POST /api/auth/register`：注册用户，不自动登录。
- `POST /api/auth/login`：返回 `access_token`、`expires_in`、`refresh_token`、`refresh_expires_in`、`token_type` 和公开用户。
- `POST /api/auth/refresh`：可恢复的续期请求。
- `POST /api/auth/logout`：撤销会话，返回 204。
- `GET /api/auth/me`：从 Bearer 请求头确认身份。

请求密码和续期凭据使用 `SecretStr`，失败响应不回显原始输入。携带凭据的响应禁止缓存；日志不读取请求体、Authorization 或响应凭据。

## 8. 前端凭据管理和调度

`auth.js` 在登录成功后调用 `AuthSession.setSession()`，将两种凭据和到期元数据作为一个记录保存在当前标签页，清空密码后进入工作台。

`auth-session.js`：

- 根据响应有效期计算时间，提前约六分之一且最多 5 分钟申请。默认 30 分钟令牌约在第 25 分钟续期；正常时只有一个到期定时器，不每几秒轮询。
- 每次成功重新安排下一次；以请求发起时间保守计时，避免响应延迟或浏览器休眠高估有效期。
- 同一时间复用同一个续期 Promise；先保存请求编号，超时或刷新页面后仍重试同一次轮换。
- 后台/休眠恢复、网络恢复时检查是否已到期，不必等下一次定时器。
- 访问 JWT 已过期，但续期窗口仍有效时，可以先续期再查询用户；只读身份查询最多自动恢复后再试一次。
- 暂时失败按 2、5、10、30 秒退避重试；离线时等待网络恢复。注册、上传等其他写请求不自动重发。
- 退出清除本标签页凭据、停止调度、取消旧续期；迟到响应不能把退出状态恢复。

`workbench-auth.js` 先确认身份，再启动调度。续期只更新账号和凭据，不重建页面、任务列表或表单，所以搜索、备注、未提交输入仍保留。会话确实无效时保留页面并提供重新登录入口。

静态预览 `?preview=1` 不启动续期，也不绕过后端认证。文件、任务仍是静态示例，真实业务归属过滤后续接入。

## 9. 运行和检查

首次或更新后应用迁移，再启动：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe dev.py
```

本机已迁移到 `0002`。旧 JWT 不带会话编号，本次更新后需要重新登录一次。

前端用模拟时钟验证，无需等 25 分钟：

```powershell
node --test frontend/tests/auth-session.test.cjs
```

后端测试覆盖过期访问令牌恢复、会话到期、轮换、同操作丢失响应恢复、重放撤销、并发、事务回滚和退出。真实 MySQL 测试需设置 `RUN_MYSQL_TESTS=1`，只清理自己创建的临时账号。

目前仍未接入失败尝试限流、会话历史定期清理。续期不能在服务端会话已失效后绕过认证。
